# 验证与测量

按[分级目标](levels.md)选取相关方法。[实验配置](../assets/experiment-profile.md)可以帮助记录影响比较和复现的条件。

## 固定实验配置

根据项目口径明确本次想验证的结论、比较对象、代表性输入和验收依据。优先记录实际运行时的配置。对需要正式验收的实验，在测量前约定指标和门槛。暂无门槛时，可以先做诊断并报告观察结果。

## 分层执行

可以从设备、框架或算子的最小用例开始，也可以直接复用已验证的模型入口。推理时确认实际执行设备，并用真实输入核对输出语义、形状、类型和异常值。合成输入可用于快速定位执行问题。涉及机器人动作时，坐标系、单位、控制语义和归一化往往比输出形状更能解释差异。

## 数值对齐

- **比较同一对象。** 选定要比较的输出、loss、梯度或任务指标，尽量使用同权重、配对输入与等价预处理，明确计算精度和后端差异。
- **控制随机性。** 自回归模型可用相同前缀比较 logits，扩散或 flow 模型可复用噪声和采样设置。跨平台使用相同 seed 时，仍应确认生成的实际输入。
- **把误差定位到可复验的范围。** 根据模型和任务选择指标、样本范围及汇总方式。出现越界时可先检查受影响样本和中间输出，再用原来的比较口径复验改动。

## 性能、资源与剖析

- **先定计时边界。** 说明是否覆盖加载、预处理、数据传输和后处理。GPU 异步执行时，选择适当的同步或设备事件，确保测量覆盖所声称的路径。
- **测稳态性能。** 预热后用短窗口测量，以实际处理的样本、token 或请求计算吞吐，按场景选择时延分位数。训练吞吐的窗口覆盖有效参数更新，包含相应的梯度累积。显存测量注明峰值口径，并区分框架分配、框架预留和设备总占用。
- **与参考卡对比。** 优先用相同的模型、权重、输入、batch、精度、卡数和计时边界。记录后端、训练策略或并发等相关差异。条件差异影响可比性时，分别说明两侧结果及其适用范围。
- **用时间线定位瓶颈。** 训练可从数据读取和准备追到参数更新，关注前向、反向、同步及通信。推理可从输入就绪追到输出可用，关注预处理、传输、模型执行和后处理。正式计时与 trace 分开采集，结合 CPU、GPU 和拷贝事件查找等待与重叠，区分 kernel 累计时长与墙钟时间。

### 按需性能分析

- **推理扫参。** 从代表性配置出发，围绕时延预算和吞吐需求选取少量 batch 值。模型支持时，再考察动作块长度和去噪步数。比较时保持其他条件可比，用任务指标复验这些改动对效果和控制行为的影响。
- **MFU 与扩展效率。** 当模型 FLOPs 可合理估算时，以单位工作量中模型前向与反向所需的 FLOPs 乘实测吞吐，再除以参与设备在相应精度下的理论峰值算力之和。跨卡对比采用一致的 FLOPs 口径，并说明估算。涉及多卡部署时，以可运行的较小规模为基准，用吞吐倍数除以卡数倍数计算扩展效率，注明基准卡数、并行策略和全局 batch 是否随卡数变化。
- **算子耗时。** 优先分析处在关键路径上的热点。两侧算子可对应时，按相同形状、精度和调用口径对比耗时。融合或后端实现有差异时，可按等价子图或功能阶段比较。
- **显存访问、Host–Device 传输和数据加载。** 热点疑似受访存限制时，查看显存读写带宽、流量与缓存行为。拷贝或同步占据关键路径时，查看传输方向、大小、耗时及计算重叠。GPU 等待数据时，检查读取、解码、预处理和数据队列。

## 按需训练、恢复与任务效果

P0 的短程训练关注实际设备、代表性数据、loss、梯度和有效参数更新。检查点恢复有验证价值时，可实际重启并核对恢复后的状态或结果。任务效果需要相应的离线评测或闭环实验，其结论取决于证据所覆盖的场景。
