# 分级执行与交付

级别描述本次希望回答的问题。已有脚本、实验记录和项目验收标准可直接作为起点。步骤、工具、样本量和资源额度按模型与任务选择。

## 开工前的最小依据

先从项目资料确认模型、目标平台和用户要做的决定。P0 重点看训练入口、代表性数据及剖析范围。P1 重点看推理入口和能核实的参考 GPU 基线。P2 从模型仓库、论文、模型卡和目标平台资料着手。缺少某项条件时，仍可推进有独立价值的验证，并指出它能回答什么。

## P0：训练、推理、精度与端到端性能

- **训练链路**。用目标 GPU 和代表性的真实训练样本验证前向、loss、反向和实际参数更新。一次有效更新通常就能验证链路，持续步数、检查点和恢复按目标决定。
- **推理**。用真实输入验证目标 GPU 上的输出与后处理，选择能代表实际用途的场景。
- **精度**。用项目认可的基线、配对输入和容差比较结果。若项目关心训练数值，再比较 loss、梯度或更新。
- **性能**。用代表性配置测短窗口的稳态训练吞吐和推理时延、吞吐，按需记录峰值显存。有可比的参考卡数据时，按相同工作负载和测量口径对比。分别采集训练和推理的端到端时间线，识别主要耗时与等待。已有性能目标时，单独判断是否达标。[评测与剖析方法](validation.md#性能资源与剖析)

## P1：推理与参考 GPU 精度对齐，按需微调

在目标 GPU 上用真实输入验证推理，再和参考 GPU 做配对比较。可复用已有基线，关键是能够核实设备、输入、配置和结果。发现数值差异时，优先从预处理、精度或算子定位。微调适用于领域适配或任务效果确有改进需求、且数据和资源可用的情况。

遇到性能异常时，可选用[性能诊断方法](validation.md#按需性能分析)定位原因。

## P2：调研收录，仅技术报告

依据官方仓库、论文、模型卡和框架文档，判断权重与许可证、关键依赖、硬件需求及目标平台风险。给出收录建议和进入 P1／P0 的前置条件，标明关键来源与证据缺口。P2 只交付技术调研报告，工作范围止于资料调研。

## 分级验收判定

用项目认可的口径说明各项目标的结果。缺少可核实的基线或验收门槛时，将结果作为诊断发现，说明还需哪些证据才能验收。某项工作未完成、失败或受阻时，说明原因及对整体结论的影响。用户只要求级别中的一部分时，按其范围交付，并写清已覆盖的部分。
