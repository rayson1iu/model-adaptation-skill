# 问题记录与交接

## 发现、修复和复验

发现安装、导入、驱动、算子、模型接口、数值、容量或性能问题时，先在模型 `docs/issues/` 按现有编号登记，再尝试修复。使用现有模板或 [ISSUE 模板](../assets/issue.md)，同步 INDEX。初次登记只写已知事实、缺失信息和下一步；不得编造原因。

每条 ISSUE 面向不了解对话的读者：开头说明触发条件、预期、实际、影响及当前结论。问题类别与状态分开，现象类别不等于已证实根因。数值超门槛导致主动退出是数值判定失败，不能仅凭非零退出码称为执行崩溃；OOM 先记录容量边界，不能未经证实归为驱动缺陷。

精度问题正文必须并列说明 reference/candidate 和可比性，按 [数值对齐](validation.md#数值对齐) 补齐条件。图表命名与正文一致，不能把比较对象藏在 JSON 或文件名中。

正文摘要关键报错、指标、单位、原门槛及实际结果。每个证据链接说明要看的字段、样本、层、时间段或关键行，以及其支持的结论。日志、JSON 和 trace 是附件，不能替代正文解释。

原因分析区分已证实事实/机制、待验证假设与未定位环节。每次尝试记录实际操作、配置/代码变更、时间、退出码、结果和证据；相关性不能写成因果，单样本不能推广到全模型。

每次尝试或复验后立即回填正文与索引。区分上游修复、局部修正、项目绕过和保守配置，解释适用范围与代价。没有实际复验不能标为已解决；部分通过须列出剩余失败范围。当前摘要不得残留与新证据冲突的“待复验”；历史状态保留日期并标明历史。

## 可视化

用图表帮助读者看清逐样本误差与门槛、配置差异、时延分布、阶段耗时或 GPU 热点。优先呈现能解释结论的少量图；简单报错或单项结果用文字或小表格即可。

每张图给出清楚的标题、比较对象、样本范围、轴与单位、适用门槛，并在图旁用一两句话说明读者应看到的差异或瓶颈。图表使用保存的真实数据，链接原始数据和生成命令。复杂的统计口径与未核实条件集中放在方法或证据说明中；会改变图表结论的限制直接写在图旁。

## 运行与持续记录

每个有意义的安装、变更、实验、诊断或复验单元结束后落盘，使用 [工作日志](../assets/work-log.md) 或已有等价索引。记录时间、目标、操作、变更、结果、证据链接、未完成项和下一步。聊天和 agent 记忆不能代替记录。

启动实验时保存 run-id、实际命令、必要参数、镜像/源码版本、开始/结束时间、退出码及日志路径。使用 tee 等管道时保留实际程序退出码，而非仅记录管道末端状态。失败、OOM、中断和无收益也记录；凭据不得进入日志。

流程状态（运行中、已结束、中断）与验收状态（未验证、通过、失败、被阻塞、不适用）分开。沿用项目已有状态名称，明确映射与范围，不能用 FINISHED 或退出码 0 替代通过。

后台任务启动时持久化进程/容器标识、阶段、日志、恢复入口，并安排阶段结束或失败后的记录更新。调度中断后先检查任务和产物再续跑；子进程存活不证明后续阶段会运行。

用户启用[本地工作看板](dashboard.md)时，在具体工作项或阶段变化及 ISSUE、报告落盘后同步看板条目；流程状态与验收判定分开写。看板是阅读入口，不能替代日志、ISSUE 或运行报告。

询问进度或交接时核查实际进程、最新日志、检查点和指标；更新过期状态。时间估计必须注明估计时点、实测速率、剩余工作及条件，条件失效则更正。

## 历史复核

只复核报告时读取原始产物、运行配置、当时版本与已有摘要，不启动新模型实验。新结论标为“复核历史结果”；缺失历史命令、配置或输入时说明不可精确复现，不能用当前版本补作历史证明。发现冲突，以实际证据修正受影响摘要，保留原始测量；没有新结论的简单解释无需重复记日志。

## 交付核对

- 新实测是否有实际命令、日志、指标/检查、判定与问题状态；证据路径是否可定位。
- ISSUE 是否说明类别、比较条件、证据、分析、修复/尝试、复验范围和下一步；图是否可读且来源可查。
- 正文、INDEX、运行报告与 WORK_LOG 是否一致；按影响更新模型 README、模型登记和工作区总览，不改无关模型。
- 自动生成文档是否修改了来源或生成逻辑，避免下一次刷新丢失补充内容。
- 失败和旧测量是否保留，当前结论是否区分未执行、失败、阻塞及部分通过。

发现遗漏先补齐再汇报。无法写入或外部条件阻塞时保存可写的交接记录，列出未回填文件、原因、证据和恢复方式，明确尚未完成的记录工作。最终回复给出关键产物的可点击路径。
