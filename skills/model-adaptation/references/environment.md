# 环境与目录

## 工作区布局

已有项目优先沿用其路径与入口。新工作区默认使用以下结构，根目录由任务指定；未指定且尚无项目布局时使用 `~/workspace`：

```text
<workspace>/
  AGENTS.md                 项目公共规范（已有则不擅自重写）
  README.md                 工作区总览
  model_zoo/<model>/        上游源码，保留 Git 历史
  repo/MODELS.md            模型登记
  repo/<model>/
    README.md               当前状态与入口
    docker/                 Dockerfile、依赖锁定与构建配置
    scripts/                可复现运行入口
    patches/                适配补丁及上游差异说明（需要时建立）
    docs/environment/       环境快照
    docs/issues/            问题正文、模板与 INDEX.md
    docs/WORK_LOG.md        工作索引
    logs/                   原始输出
    reports/runs/<run-id>/  配置、测量、报告与证据索引
    .cache/                 模型专属缓存
```

只建立当前任务需要的目录。新增模型更新登记；迁移时同步脚本、构建上下文、挂载和链接，历史原始日志与 JSON 不改写，用迁移记录解释旧路径。

## 环境准备

- 先确认架构、显卡厂商和设备、驱动、SDK/runtime、Python 与框架版本，再选择镜像及依赖。记录来源和版本，不能把 NVIDIA CUDA 构建安装到需要保留 MACA 框架的环境中。
- 默认每模型独立 Docker 镜像；固定基础镜像 digest、源码提交、依赖版本及实际运行镜像 ID。保留构建与安装命令、变更理由和补丁。
- 不直接修改系统 Python、共享 conda 或服务器驱动。正式模型验证在容器内进行；宿主仅用于项目已有的探测、下载和调度准备。
- 容器使用当前 UID/GID，名称包含用户与模型标识，显式配置 CPU、内存和共享内存限额。按实测需求设置，不沿用其他模型的固定额度。
- 仅映射获选 GPU 及厂商必需公共设备节点；避免 privileged、host PID/IPC/network。需要扩大映射时先记录必要性与证据，遵循项目权限边界，不把排错当成无限制提权授权。
- 每次运行前检查 GPU 占用和磁盘、内存余量；卡号可配置，遇到新占用换空闲卡或等待。Docker 和本项目锁均不保证跨用户 GPU 独占或显存配额。
- 不停止他人进程/容器，不清理他人文件，不执行全局 Docker prune；长期负载按项目约定协调资源。
- 源码、缓存、日志和报告持久化到工作区并明确挂载。不要将唯一证据留在临时容器中。

## 跨平台与远端对照

仅在任务包含跨平台对照时使用。读取项目接入规范，确认目标、用户、控制端、传输方式和资源条件；不从示例猜测服务器地址或凭据。

各平台保留本地适用的厂商框架和架构镜像，不跨 ARM/x86 复用二进制 wheel。尽量对齐源码、模型组件、权重、数据划分、统计、输入 fixture、有效 batch 和精度；无法一致的条件明确列为差异。

远端产物使用摘要校验后回传到项目主归档，并保留来源路径与 run-id；不自动删除远端产物。平台连接、基础算子就绪和完整模型基准分别登记。未完成可比模型测量时不发布加速比；容量或依赖不足时记录阻塞条件和下一步，不自动清理或扩大任务。
