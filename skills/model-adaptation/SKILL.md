# 模型适配与验证

将模型适配任务交付为便于阅读的结论、可复现的操作和真实证据。默认使用中文说明，技术标识保留原文。

## 调用参数与适配级别

在请求中使用 `level=P0|P1|P2` 指定工作深度，例如：

```text
$model-adaptation level=P1
模型：OpenVLA-OFT
工作区：/workspace/openvla
目标平台：待适配 GPU
参考 GPU：项目指定的基线 GPU
```

这是由本 skill 解释的输入约定，不是终端命令或 Codex 原生 CLI 参数。也接受 `level=p1`、`级别：P1` 等明确的等价写法，记录时统一为大写。

| level | 必需范围 |
| --- | --- |
| P0 | 训练 + 推理 + 精度对齐 + 端到端性能剖析 |
| P1 | 推理跑通 + 与参考 GPU 精度对齐；根据证据与任务条件决定是否微调 |
| P2 | 调研收录，仅输出技术报告，不执行模型适配或实验 |

指定级别后，先读取 [分级执行与交付](references/levels.md)，确定必需阶段、前置条件与验收依据。P0 的训练不能用一次反向传播代替；P1 不自动启动微调；P2 不安装依赖、创建容器、下载权重或运行训练/推理/基准测试，也不额外创建实验日志或 ISSUE。

未提供 `level` 时按用户明确的任务范围执行，不默认提升为 P0 或 P1。参数值不受支持、重复值互相冲突，或级别与明确限制冲突时，在执行受影响的工作前澄清；明确只复核历史结果的请求保持只读复核。用户明确缩小范围时，记录为该级别的范围裁剪，不将其报告为完整级别验收通过。

## 先确定本次工作

1. 阅读目标工作区适用的 AGENTS.md、模型登记、模型 README 和相关方法文档；检查已有运行入口与产物。沿用已有规范，不因启用本 skill 重建项目。
2. 从用户请求确定适配级别（如有）、模型、工作区、平台、目标阶段和交付物。先按调用参数限定范围；P2 直接进入调研报告流程，不执行后续实测步骤。只复核旧报告时仅读取证据；未指定分级且只做推理兼容性时不启动完整训练、闭环或跨服务器实验。使用已有授权；仅在缺少会改变实验含义的信息时询问。
3. 区分本次新实测、历史复核和诊断实验。执行前确定配置、run-id、日志及报告位置；不要用当前源码或环境冒充历史运行版本。
4. 根据任务读取下表中的相关参考，不必一次加载全部资料。

| 当前工作 | 阅读内容 | 可用模板 |
| --- | --- | --- |
| 指定 P0/P1/P2 级别、确定范围与分级交付 | [分级执行与交付](references/levels.md) | P0/P1 使用实验配置与运行报告；P2 按参考中的技术报告结构交付 |
| 新模型接入、依赖、容器、设备或跨服务器准备 | [环境与目录](references/environment.md) | [实验配置](assets/experiment-profile.md) |
| 推理、数值对齐、性能、训练恢复或任务效果验证 | [验证与测量](references/validation.md) | 实验配置、[运行报告](assets/run-report.md) |
| 故障、数值失败、报告复核、阶段交付或后台任务交接 | [问题与交接](references/issues-and-handoff.md) | [ISSUE](assets/issue.md)、运行报告、[工作日志](assets/work-log.md) |

模板用于填入真实信息；已有等价文档时合并必要字段，不覆盖原文或重复建档。未知项说明原因和下一步，不编造内容填满模板。

## 报告写给人看

报告先用简洁摘要说明完成了什么、关键结果、判定和下一步，再用少量表格或图展示最能支撑结论的证据。按读者的判断路径组织正文，不把实验配置、原始日志和每次排错过程直接堆进正文；这些细节放在附录、Profile、ISSUE 或可点击的证据链接中。

精度误差分布、训练趋势、时延分布、阶段耗时或 GPU 热点等图表，在能帮助读者看清差异和瓶颈时使用。图表来自真实数据，标明对象、样本范围、轴与单位、门槛，并用一两句话解释发现；简单结果用文字或表格即可。

用直接、明确的语言写结论。失败、阻塞和会改变判断的限制必须如实说明；一般性的条件说明集中在“范围与限制”或证据附录，避免每句结论后都接重复的防御性表述。P0/P1 参考[运行报告模板](assets/run-report.md)，P2 按[分级执行与交付](references/levels.md#p2调研收录仅技术报告)写技术报告。

## 全程保持的约束

- 使用每模型独立容器并固定环境；保护共享宿主环境、厂商框架和其他用户资源。卡号、资源限额、工作区与远端目标按项目配置，不固定为某台服务器的值。
- GPU 验证不得静默回退 CPU。CPU 可作为显式参考，但不能证明 GPU 适配通过；合成输入仅证明所测执行路径，不能证明任务效果。
- 明确 reference/candidate 及输入、权重、存储精度、计算精度和后端条件。正式测试前冻结验收门槛；缺少基线或门槛时如实标明，不通过事后放宽门槛获得通过。
- 发现问题先记录已知事实，再尝试修复；保留原始错误、失败、OOM、中断和无收益尝试。只有实际复验支持的范围才能标为已解决。
- 实测、修复或历史复核工作单元结束后及时保存结果并同步受影响文档；P2 将结果与来源集中于技术报告，不额外建立实验记录。退出码为零、调度结束、安装成功都不能替代验收通过。
- 默认结构化记录使用 Asia/Shanghai 并标明时区；项目另有明确约定时沿用。原始日志时间与内容保持原文。凭据不进入命令行、文档、日志或版本库。

## 最小交付

新实测交付：实际命令、版本及条件、原始日志、指标或检查结果、明确判定、问题状态及下一步。历史复核交付：被核对的产物、发现和证据缺口，并明确未执行新实验。

指定级别时同时说明目标级别、实际完成阶段和未完成项。P2 交付技术报告，明确仅调研、未执行新实验，不以调研结论宣称适配通过。必需阶段缺失、失败或被阻塞时，不自动降级或宣称目标级别完成。

结束前按 [交付核对](references/issues-and-handoff.md#交付核对) 检查文档一致性，向用户提供关键产物的可点击路径。无需为了形式修改无关模型或对没有新结论的简单解释重复记日志。

## 规范来源与适用边界

本 skill 提炼自原工作区的 AGENTS.md、SmolVLA/OpenVLA-OFT 验证方法及 ISSUE 模板；运行时不依赖这些源文件存在。其目录结构和记录方式作为默认约定，项目现行规范与用户明确要求优先。

《具身智能模型统一评测规范 V0.5》仅提供配置固定、动作语义、测量边界等方法参考，不作为必做清单。不继承其测试编号、固定样本数和迭代数；不固化历史模型的数值门槛、默认卡号、服务器地址、版本或故障结论。
