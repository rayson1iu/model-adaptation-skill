# 模型适配与验证

依据用户目标和项目规范选择合适的适配路径。具体工具、步骤、样本规模、目录和记录粒度随任务而定，优先复用项目已有的环境、脚本和产物。

## 选择工作深度

在请求中使用 `$model-adaptation level=P1`，也可写 `level=p1` 或“级别为 P1”。省略 `level` 时按用户描述的范围工作。

| 级别 | 工作目标 |
| --- | --- |
| P0 | 验证目标 GPU 的短程训练与推理，完成精度对齐和端到端性能剖析。短程训练旨在验证前向、反向和实际参数更新，训练规模由任务决定。 |
| P1 | 在目标 GPU 跑通推理，并与参考 GPU 对齐精度。根据任务效果和资源条件决定是否微调。 |
| P2 | 调研模型及目标平台的适配可行性，给出收录建议，仅交付技术调研报告。 |

具体目标和证据示例见[分级执行与交付](references/levels.md)。历史复核依据当时的配置和产物。用户只要求复核时，范围限于已有证据。

## 选择验证方法

- **先明确结论要回答的问题。** 确认目标平台、适配范围和已有证据。条件不足时，先做能推进判断的调研或诊断，并说明哪些结论需要补证据。
- **从最小可验证路径入手。** 优先跑通有代表性的输入。遇到故障时，从依赖、设备、算子、权重或输入中选择最可能缩小问题的检查。
- **对齐比较条件。** 明确实际执行设备、基线、输入、权重和精度。正式验收沿用项目约定的指标与门槛，说明仍可能影响结果的差异。
- **让证据支撑结论。** 区分实测、诊断和历史复核。对照目标说明完成项、失败或阻塞及下一步，链接读者需要的关键证据。

## 写给读者的交付物

先写结论、关键结果和下一步，再附证据链接。文字和表格是默认形式，只有用户明确要求时才画图。单纯的网络下载失败按需记录在工作日志或交接说明中，不建 ISSUE。
